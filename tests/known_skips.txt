# tests/known_skips.txt -- THE SINGLE AUTHORISITIVE LIST OF PERMITTED SKIPS.
#
# One line per test that CTest reports as Skipped. The first whitespace-separated
# field is the CTest test NAME; everything after it is prose and is not parsed.
# Blank lines and lines beginning with '#' are ignored.
#
# WHAT THIS IS FOR. 6.4 of docs/SERVER_DESIGN.md used to describe a KNOWN_SKIPS
# list that did not exist, and Phase 7 implements the gate it described -- as a
# RATCHET rather than as "zero skips", because "zero" is unreachable before Phase
# 9 and the reasons are in 6.4. The ratchet enforces the real intent: the count
# only goes DOWN, and every skip is accounted for by name, by the phase that owns
# it, and by the issue that closes it.
#
# THE GATE FAILS IN BOTH DIRECTIONS, and the second direction is the one that
# makes this a ratchet rather than an allowlist that can rot:
#
#   a test that skips and is not on this list        -> FAIL (a new skip)
#   a test on this list that no longer skips         -> FAIL (a retired skip
#                                                          that was not retired
#                                                          from the list)
#   a name here that is not a registered CTest test   -> FAIL (a typo, or a test
#                                                          that was deleted)
#
# Enforced by scripts/check-skips.sh, which CI runs and local-ci.sh runs. The
# other half of the rule -- "the list is the only place a skip is permitted" -- is
# CONTRIBUTING.md's, and it is what the first direction enforces: a new skip
# without a line here is red.
#
# CLOSING A SKIP. Implement the feature, delete the `return 77` and the
# SKIP_RETURN_CODE in the test's CMakeLists.txt, and DELETE THE LINE HERE IN THE
# SAME CHANGE. Leaving it is a CI failure, which is the point: the list is meant
# to be hard to leave stale.
#
# Zero skips is still the goal. Phase 8 retired the two IRCv3 lines that were
# here (CapNegotiation and MultiPrefix) and Phase 9 retires the five that
# remain, and when the last line goes this file is empty and the gate is a plain
# "no test may skip".
#
# --- the list -----------------------------------------------------------------

# EMPTY. The list has no lines, and that is the state 6.4 always said the goal was.
#
# PHASE 9 RETIRED ALL FIVE of the skips this file existed to account for:
# SyncState, FailoverReconnect, Reconnect, PeerDiscovery and AutoScale. Each was
# retired the way the rules above ask -- the feature implemented, the `return 77`
# and its SKIP_RETURN_CODE deleted, and the line deleted HERE IN THE SAME CHANGE --
# and each moved to a file of its own in tests/integration/ with its CTest name
# UNCHANGED, because this file names tests by that name and
# scripts/check-skips.sh checks every listed name against the registered set in both
# directions. Renaming a test to suit a build system is how a line here goes stale
# without anybody noticing; renaming the TARGET and keeping the CTest name is the
# move that keeps the ratchet honest.
#
# WHY EACH OF THE FIVE NEEDED A FILE OF ITS OWN, since that is the part of the
# history this file is for and the reasons are not the same:
#
#   Reconnect          a client whose TCP session drops and comes back gets its
#                      channel set back. Only observable over a socket, by a client
#                      that really connects and really disconnects.
#   PeerDiscovery      a peer advertises a DIAL HINT and this node records it and
#                      NEVER dials it -- the SSRF claim. Not observable on the node
#                      holding the hint, because a guard that prints `dialed=NO` and
#                      then dials anyway passes an assertion on its own log. It
#                      needed a THIRD node for the hint to point at.
#   AutoScale          a node announces its OWN departure and its peers treat it as
#                      terminal rather than as a failure. Needs a mesh, and the
#                      origination cannot be tested by writing the line by hand:
#                      fed_send_shutdown() now has exactly one caller
#                      (server_shutdown()), and a departure produced by a test rather
#                      than by a node proves nothing about whether a node produces
#                      one.
#   FailoverReconnect  the retry POLICY's shape: backoff, a cap, a budget that is
#                      spent and reported.
#   SyncState          that the 4.3 resync is DRIVEN by a reconnect, and that what
#                      it drives REPLACES rather than merges.
#
# ALL THREE FILES WERE CLASSIFIED HERE BY THE SKIP'S NAME RATHER THAN BY THE
# FEATURE, and it was wrong in the same way for all of them: none is a property of a
# single node, and a target in tests/loadbal/ links irc_core and nothing else -- it
# cannot spawn a node, cannot own one end of a link, cannot drop a socket and cannot
# read a 366. That is why all three were ten-line placeholders, and why implementing
# the features in place was not possible. tests/loadbal/CMakeLists.txt is now a
# directory of no tests and says so.
#
# ---------------------------------------------------------------------------
# WHAT THE GATE IS FROM HERE ON, AND WHY THE FILE STAYS
# ---------------------------------------------------------------------------
# The gate is "no test may skip", which is the phrase 6.4 always said the goal was.
# The rules at the top of this file are all still in force and all still enforced --
# a test that skips without a line here is red -- and with no lines, every test that
# skips is red. So the FIRST direction of the gate became total rather than
# conditional, and the other two have nothing to check and pass vacuously.
#
# THE FILE IS KEPT AND NOT DELETED, and this is the one thing that changed shape when
# the list emptied: check-skips.sh fails on a MISSING list, deliberately, because a
# test that skipped with no list would otherwise be permitted by the accident of the
# file's own absence. The gate's own header says so. So an empty file is the
# finished state and an absent one is a broken gate, and the difference between them
# is not visible from the gate's behaviour alone -- which is why this paragraph
# exists rather than being left to whoever runs `git log`.
#
# ADDING A LINE BACK IS ALLOWED and needs no change to the script: a developer who
# genuinely cannot implement something writes the line and the skip is red until
# they do. That is still the whole point of the file, and it is why the header's
# "CLOSING A SKIP" paragraph remains the instruction rather than a historical note.
