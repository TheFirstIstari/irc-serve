# tests/known_skips.txt -- THE SINGLE AUTHORISITIVE LIST OF PERMITTED SKIPS.
#
# One line per test that CTest reports as Skipped. The first whitespace-separated
# field is the CTest test NAME; everything after it is prose and is not parsed.
# Blank lines and lines beginning with '#' are ignored.
#
# WHAT THIS IS FOR. 6.4 of docs/SERVER_DESIGN.md used to describe a KNOWN_SKIPS
# list that did not exist, and Phase 7 implements the gate it described -- as a
# RATCHET rather than as "zero skips", because "zero" is unreachable before Phase
# 9 and the reasons are in 6.4. The ratchet enforces the real intent: the count
# only goes DOWN, and every skip is accounted for by name, by the phase that owns
# it, and by the issue that closes it.
#
# THE GATE FAILS IN BOTH DIRECTIONS, and the second direction is the one that
# makes this a ratchet rather than an allowlist that can rot:
#
#   a test that skips and is not on this list        -> FAIL (a new skip)
#   a test on this list that no longer skips         -> FAIL (a retired skip
#                                                          that was not retired
#                                                          from the list)
#   a name here that is not a registered CTest test   -> FAIL (a typo, or a test
#                                                          that was deleted)
#
# Enforced by scripts/check-skips.sh, which CI runs and local-ci.sh runs. The
# other half of the rule -- "the list is the only place a skip is permitted" -- is
# CONTRIBUTING.md's, and it is what the first direction enforces: a new skip
# without a line here is red.
#
# CLOSING A SKIP. Implement the feature, delete the `return 77` and the
# SKIP_RETURN_CODE in the test's CMakeLists.txt, and DELETE THE LINE HERE IN THE
# SAME CHANGE. Leaving it is a CI failure, which is the point: the list is meant
# to be hard to leave stale.
#
# Zero skips is still the goal. Phase 8 retired the two IRCv3 lines that were
# here (CapNegotiation and MultiPrefix) and Phase 9 retires the five that
# remain, and when the last line goes this file is empty and the gate is a plain
# "no test may skip".
#
# --- the list -----------------------------------------------------------------
#
# NOT EMPTY YET: Phase 9 has retired four of the five (SyncState,
# FailoverReconnect, Reconnect and PeerDiscovery) and one remains below, owned by
# the last item of the same phase. Reconnect's line is gone because the feature is
# implemented and its test is a real socket-level test rather than a
# placeholder -- tests/integration/test_reconnect.c, with the CTest name
# unchanged. PeerDiscovery's is gone for the same reason and the same move --
# tests/integration/test_peer_discovery.c, CTest name unchanged -- and the reason
# its test needed a file of its own is the one worth writing down here: a peer
# that advertises a DIAL HINT cannot be caught by a node asserting on its own
# logs, because a guard that prints `dialed=NO` and then dials anyway passes that
# assertion. It needed a THIRD node for the hint to point at. This comment block
# is the place the final one goes: when the last line below is deleted this file
# holds comments and nothing else, and that is
# different from the file being absent -- check-skips.sh fails on a MISSING list,
# and a test that skipped with no list would otherwise be permitted by the
# accident of the file's own absence. Every rule above still applies then, and
# the gate is "no test may skip", which is the phrase 6.4 always said the goal
# was.
